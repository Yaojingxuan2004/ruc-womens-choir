# RUC女子合唱团网站 用Vibe coding组织一份可浏览的合唱团档案

**2026.08｜个人兴趣项目｜JavaScript与AI协作开发**

[Sites作品](https://ruc-womens-choir.yaojingxuan2004.chatgpt.site/)

### 1. 起点与目标

我希望借网站宣传合唱团，让想了解我们的人能够浏览演出、成员、照片和相关资料。需求来自我在团内的经历与兴趣，不包装成已完成正式访谈的商业委托。我的JavaScript基础用于理解与修改页面，后续视觉与交互改进使用AI协作完成，不把所有代码都写成独立手写。

### 2. 把“宣传”拆成访客能完成的事

现有网站把内容组织为首页、演出、成员、荣誉、相册和指挥介绍。首页承担认识合唱团与进入内容的入口；演出页连接具体专场和节目；相册支持查看图片；荣誉与指挥资料提供进一步了解的背景。

这一结构可以按访客任务解释：第一次来先了解“这是什么团”，有兴趣再看“唱过什么、是什么样的活动”，需要更多信息时进入成员与指挥资料。这是本轮对已有页面的产品逻辑梳理，不倒写成制作前已开展完整用户研究。

### 3. 交互为内容服务

节目单使用展开式浏览，减少长内容对页面扫读的影响；相册支持放大查看。现有JavaScript还处理移动导航、Escape关闭、当前导航状态，以及关闭图片后把键盘焦点返回原入口。它们对应的是“找得到、看得清、关得掉、回得去”，而不只是页面有动画。

这些是源文件可核对的实现，不等于已经覆盖所有浏览器或通过真实用户测试。当前内容核查沿用既有4场专场与13个相册条目的口径，不将条目数量写成用户数或活动增长。

### 4. 实现与发布取舍

内容以展示为主，因此当前采用静态网页，避免为没有明确需求的功能增加登录与后台。现有项目也包含用于Sites构建的包装配置；展示页的主体仍位于静态目录。Sites发布记录可核对，本轮没有重新部署。

已有反馈指出中国大陆朋友访问Sites域名遇到问题。对宣传网站来说，“能否打开”本身就是体验的一部分；后续应验证目标访客网络下的可达性，并在需要时选择合适的托管方式。当前没有完成迁移，不能宣称已解决大陆访问问题。

### 5. 价值与边界

这个项目的当前价值是将合唱团资料集中为可浏览、可分享的作品，展示我把需求转成内容结构和交互的能力。没有真实流量、招生、报名或传播转化数据，不写“提升宣传效果X%”，也不将网站等同官方持续运营渠道。

如果以后正式服务合唱团，可以先观察访客能否找到演出信息、图片打开是否顺畅、移动端是否易读及内容维护是否方便。商业价值在此更接近组织传播与维护效率，不需要强行虚构付费模式。这些是后续评估建议，不是已采集指标。
